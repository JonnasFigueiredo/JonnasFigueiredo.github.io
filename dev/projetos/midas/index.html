API financeira com invariantes, concorrência e testes de integração.

API de contas e transações construída para demonstrar regras financeiras, consistência de dados e uma estratégia de testes que consulta tanto o contrato HTTP quanto o banco.

Ver código no GitHub ↗Conversar sobre o projeto ↗

O problema

Uma API de transações precisa continuar correta quando há falhas, atualizações concorrentes e operações que afetam mais de uma conta.

A solução

A API usa persistência relacional e migrações versionadas. A suíte de integração sobe o ambiente em contêineres e verifica respostas HTTP, estado do MySQL e invariantes contábeis.

Decisões técnicas

01

Verificação por dois caminhos

Os testes conferem o contrato da API e os dados persistidos, detectando respostas corretas que escondam um estado incorreto.

02

Concorrência como comportamento

Cenários paralelos exercitam débitos e atualizações com ETag, em vez de validar apenas chamadas sequenciais.

03

Transferência atômica

O fluxo atualiza as contas e registra as duas movimentações como uma transação única, com rollback em caso de falha.

Estado e próximos passos

É um projeto de API e qualidade de backend; não há interface web de produto neste repositório.
